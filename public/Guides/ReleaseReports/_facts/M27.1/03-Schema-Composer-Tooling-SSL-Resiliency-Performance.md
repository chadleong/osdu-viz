3. **Schema Composer Tooling — SSL Resiliency & Performance**
    1. Fixed PPDM SSL certificate errors during reference data fetch — `Utility.url_retrieve_file()` was disabling certificate verification for the entire process (`ssl._create_default_https_context = ssl._create_unverified_context`). Replaced with a request-scoped, verified `ssl.SSLContext`; when the server does not send its full certificate chain, the missing intermediate certificate is now recovered from the leaf certificate's Authority Information Access extension.
    2. Added an upfront `java` availability check (`OsduApp.__assert_java_available()`) so a missing Java runtime is reported before the long-running generation stages start, instead of failing deep inside a jar subprocess call.
    3. Added Windows file-lock retry helpers (`Utility.remove_with_retry()`, `Utility.move_with_retry()`) so a transient antivirus/indexer lock on a just-written file no longer aborts the run.
    4. Batched PlantUML diagram rendering (one JVM launch per chunk of up to 100 diagrams instead of one per diagram) and parallelised the independent JVM comparisons in `BreakingChangeDetection` and `SchemaUpgradeConfigurationTester` using a thread pool, reducing a full schema generation run from roughly 1,000s to about 715s (~28% faster) with no change in generated output. Fixed the schema upgrade tester's temporary spec-file naming so concurrent migrations no longer collide.
    5. Added `Scripts/Timing.py` — lightweight wall-clock instrumentation (`timings-report.md`) breaking a run down by stage and by repeated operation, to make future performance regressions visible.
    6. Added a repo-wide [`.gitattributes`](../.gitattributes) (`* text=auto eol=lf`) — several generator scripts write tracked deliverables in Windows text mode, which silently converts line endings to CRLF and produced a spurious "every file changed" diff with no real content change. Commits and checkouts now normalise to LF regardless of platform, with explicit `binary` declarations protecting workbooks, images, and domain well-log/seismic formats from any attempted text conversion.
    7. Fixed the root cause of the CRLF churn described above. Python text-mode writes on Windows translate `\n` to `\r\n` unless `newline` is set, so every regeneration on a Windows machine rewrote generated files with CRLF line endings. Added `newline="\n"` to all 29 text-mode `open()` writes across 15 generator scripts, including the shared writers `Utility.save_json()` and `Utility.save_md()` (which produce the reference value manifests and E-R documentation), the ActivityTemplate generators, `OsduSpellChecker`, and the EPSG, UoM, cost unit and Energistics reference value generators. Generated output is now LF on every platform, with no change in behaviour on Linux or macOS. As part of the same change, renormalised the 20 files that had been committed with CRLF before `.gitattributes` was added (line endings only, no content change).
