1. **Process & Script Improvements — Data Definitions Portal & Schema Data Quality Tooling**
    1. Added a new Schema Data Quality (DQ) toolchain — [`Scripts/SchemaFragmentStalenessChecker.py`](../Scripts/SchemaFragmentStalenessChecker.py) (detects preferred schemas still referencing an out-of-date `$ref` fragment version) and [`Scripts/SchemaStatusChecker.py`](../Scripts/SchemaStatusChecker.py) (tracks schema lifecycle status, e.g. `DEVELOPMENT` vs `PUBLISHED` vs `OBSOLETE`), unified by [`Scripts/SchemaDataQualityReporter.py`](../Scripts/SchemaDataQualityReporter.py). Wired into OsduApp as a new **Run schema data quality checks** menu item: it scans preferred schemas once, appends a timestamped snapshot to [`_doc/SchemaDataQuality/DataQualityLog.json`](../_doc/SchemaDataQuality/DataQualityLog.json), refreshes the Markdown trend report ([`_doc/SchemaDataQuality/README.md`](../_doc/SchemaDataQuality/README.md)) with Mermaid charts, and regenerates a `DataQuality:2.0.0`-conformant record ([`_doc/SchemaDataQuality/LatestDataQuality.json`](../_doc/SchemaDataQuality/LatestDataQuality.json)).
    2. Added [`_doc/SchemaDataQuality/Generate_DQ_Dashboard.py`](../_doc/SchemaDataQuality/Generate_DQ_Dashboard.py), which reads `DataQualityLog.json` and renders an interactive HTML DQ dashboard (stale-fragment trend, compliance score, schema status distribution). Wired into `SchemaDataQualityReporter.main()` so it regenerates automatically on every DQ check run, and independently invoked by the GitLab Pages CI job so the published dashboard always reflects the latest committed data, without needing the local preview file to be committed (it's gitignored).
    3. Stood up a single **Data Definitions dashboard portal** ([`Scripts/PortalBuilder.py`](../Scripts/PortalBuilder.py)), published via GitLab Pages at [osdu.projects.opengroup.org/subcommittees/data-def/work-products/schema](https://osdu.projects.opengroup.org/subcommittees/data-def/work-products/schema/), bringing together three tiles: the new DQ Dashboard, a placeholder Schema Graph Model view (sourced from the in-progress LDM PoC branch `883-logical-data-models-linkml`, for demo purposes only, until that work is approved and merged to master), and the new Release Reports index described below.
    4. Added a **Release Reports** capability: [`Guides/ReleaseReports/`](../Guides/ReleaseReports) holds one static HTML report per milestone release, content sourced from the corresponding `E-R/ChangeReport.md` entry. [`Scripts/ReleaseReportIndexBuilder.py`](../Scripts/ReleaseReportIndexBuilder.py) auto-discovers every report in that folder and generates a newest-first index page, so the list scales without hand-maintaining links as more milestones ship. The first report, [`Guides/ReleaseReports/M27.0.html`](../Guides/ReleaseReports/M27.0.html), covers Milestone M27.0. Going forward the intent is to deliver one of these per Major (or Minor) release at minimum; generating them from `ChangeReport.md` automatically, using this initial report as the template, is planned as a follow-up. A subsequent iteration added [`Scripts/ReleaseReportFactExtractor.py`](../Scripts/ReleaseReportFactExtractor.py), which mechanically extracts structured facts (schema names/versions, breaking changes, migration-guide counts) from a `ChangeReport.md` milestone section to seed that drafting step — see [`Guides/ReleaseReports/README.md`](../Guides/ReleaseReports/README.md) for the full process.
    5. Added [`.gitlab-ci.yml`](../.gitlab-ci.yml) `pages` job to build all three portal components on every `master` pipeline run (DQ dashboard, graph model placeholder, release reports index, portal page), restricted to `master` so an unrelated feature branch push can't silently overwrite the shared Pages site. Since GitLab Pages only ever deploys from the default branch, a `trigger_pages_rebuild` job was added so that pushes to the LDM PoC branch (`883-logical-data-models-linkml`) automatically kick off a fresh `master` pipeline, keeping the published Schema Graph Model tile in sync with that branch's latest work without needing a manual pipeline run.
